# 原项目与本次重写

## 原研究目标

日本动物史研究希望考察犬类相关事件与城市空间的关系。初期计划利用日本国立国会图书馆已有 OCR 成果获取两部史料文本，经模型抽取后关联坐标，最终导入 ArcGIS Pro。OCR 文本是计划的史料来源；地名坐标库则来自 NIHU 与 H-GIS 研究会，两者不可混淆。

原工程记录包含 `工程.py` 与 `index.html`：Python、FastAPI、Uvicorn、OpenAI SDK／ModelScope／MiniMax-M2.5、Pydantic／JSON、PostgreSQL／psycopg2，以及 HTML／JavaScript／Tailwind CSS。代码中写有名称精确匹配、按行分块、字段校验及前端展示；没有看到地名导入脚本、抽取结果写库或 ArcGIS 接入。代码中“LangChain 工作流”注释不代表实际使用 LangChain。

本地未重新执行原来的服务，本次复现依据是此前聊天中保存的代码读取记录及用户提供的复盘，不是原系统运行验收。

## 未继续接入 ArcGIS 的原因

第一类原因是可靠定位需要额外历史考证，主要有两项问题：

1. “御所”“宅内”“家内”等表达依赖叙述者、时间、住所和上下文。用户曾尝试 AI 与联网检索，但案例中的公开证据不足，若继续推进，需要补建人物与住所、地点异名、适用年代及文献依据的参考资料库，成本主要在资料搜集与核验。
2. 同一地名对应多个真实地点。用户尝试以经纬度范围限定京都，但现代城市边界不能直接代表研究时期的京都，需要另行论证历史空间范围，与论文核心问题偏离。

第二类原因是实际研究需求发生变化：接受导师建议后，范围收缩为与论文问题直接相关的宠物犬等事例，最终只有 10 条。逐条查证已能满足研究需求，继续开发批量 GIS 导入的收益有限。

因此，ArcGIS 应写为“原计划／后续计划”，不能作为已完成成果。可以在简历简述核验困难与范围调整，把上述完整原因留在此处及面试中。
