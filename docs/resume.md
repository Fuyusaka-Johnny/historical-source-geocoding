# 简历 STAR 文案

以下按研究用途、协作过程、问题识别与研究取舍组织，不把代码实现写成个人独立开发。岗位为 AI 产品商业化运营时，正文保留研究与判断，一行技术环境供参考即可。

## 可用于简历的原项目表述

**日文史料信息抽取与地名匹配项目**

- 围绕日本动物史研究中史料信息分散、地点难以关联的需求，提出将日期、人物、地点和事件结构化，并进一步接入 ArcGIS 的应用设想；向协作者说明研究用途与预期流程。
- 提供史料与公开历史地名数据，配合协作者及 AI 探索“模型抽取—地名库匹配—原文核验”流程；结合项目复盘，归纳空间指代不明、同名地点难以判断等问题及检索、坐标范围筛选方案的局限。
- 根据导师建议将范围收缩至 10 条与论文相关的事例，结合地点核验成本确定人工查证方案；ArcGIS 接入保留为后续计划。

**原项目技术环境：**Python、FastAPI／Uvicorn、OpenAI Python SDK／ModelScope API、MiniMax-M2.5、Pydantic／JSON、PostgreSQL／psycopg2、HTML／JavaScript／Tailwind CSS；程序实现由协作者及 AI 辅助完成。

## STAR 对应

| 要素 | 文案中的内容 |
| --- | --- |
| S 情境 | 日本动物史研究中史料分散、地点难以关联 |
| T 任务 | 结构化史料信息、关联地名坐标并规划地图展示 |
| A 行动 | 提出用途、提供材料、参与协作和问题复盘 |
| R 结果 | 原型探索明确定位难点，研究收缩至 10 条并采用人工查证 |

“提供材料、归纳问题、尝试方案”等动词仍须与本人真实参与相符。若方案由朋友实施，面试应说明“我提出问题／参与讨论，朋友实现”。不要把未亲自完成的程序测试写成“验收通过”。

## 重写版未来补充方式

在亲自运行、核对样本并留下记录之后，可增加“项目复盘后迭代 MySQL 核验原型”的独立说明，并附 GitHub 链接。此时技术环境替换为 MySQL／PyMySQL 和本地 CSS；不能同时把 PostgreSQL 与 MySQL 写成同一版本当前使用的数据库。

数据规模应写“采用源数据约 29.9 万条记录的公开地名数据”，不能写成“本人处理 29.9 万条史料”“准确定位 29.9 万个地点”，也不能未经核查就说已完整导入 29.9 万条。
